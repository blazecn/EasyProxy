# 规则管理功能设计

## 概述

在代理规则页面增加自定义规则的「添加」和「搜索」功能。

当前状态：规则页面只读展示订阅中的规则，无可交互操作。

## 交互设计

### 页面结构

规则页面分为两层：

- **顶栏**（固定）：搜索框 + 「+ 添加规则」按钮
- **Tab 区**：「自定义规则」（默认）| 「订阅规则」

### Tab 行为

| Tab | 内容 | 操作 |
|-----|------|------|
| 自定义规则 | 用户手动添加的规则 | 可删除（点击 ×） |
| 订阅规则 | 来自当前订阅的规则 | 只读展示 |

搜索框覆盖两个 Tab，输入后实时过滤当前 Tab 中的规则列表（大小写不敏感）。

### 添加规则弹窗

简化模式：用户无需了解 Clash 规则类型，只需输入匹配值 + 选择策略。

**表单字段：**

- **匹配值**（文本输入）：域名、关键词，或 IP/CIDR 地址
- **策略**（三选一按钮）：Proxy / DIRECT / REJECT

**自动类型识别：**

| 输入示例 | 自动生成规则 |
|---------|-------------|
| `google.com` | `DOMAIN-SUFFIX,google.com,Proxy` |
| `github` | `DOMAIN-KEYWORD,github,Proxy` |
| `192.168.1.0/24` | `IP-CIDR,192.168.1.0/24,Proxy` |

规则类型判断逻辑：
- 包含 `://` → 不允许（报错提示）
- 匹配 IP/CIDR 格式 → `IP-CIDR`
- 匹配域名格式（含 `.`）→ `DOMAIN-SUFFIX`
- 纯关键词（无 `.`）→ `DOMAIN-KEYWORD`

**验证：**
- 输入为空时，「添加」按钮禁用
- 规则已存在时不重复添加（提示用户）

### 搜索行为

- 搜索框输入时实时过滤当前 Tab 的规则列表
- 空搜索框时显示全部规则
- 无匹配时显示「未找到匹配的规则」

## 数据存储

自定义规则存储在 localStorage：

- **Key**: `easyproxy.customRules`
- **Value**: `string[]` — 规则字符串数组，如 `["DOMAIN-SUFFIX,openai.com,Proxy", ...]`

订阅规则仍来自当前激活订阅的 `rules` 字段，不做修改。

## 影响范围

**仅前端修改**，不涉及 Rust 后端：

- `src/App.tsx` — 规则页面 UI（Tab 切换、搜索、添加弹窗、删除）
- `src/App.css` — 新增样式（Tab、弹窗、搜索框）

## 边界情况

- 无订阅数据时：订阅规则 Tab 显示「暂无规则数据」
- 无自定义规则时：自定义规则 Tab 显示「暂无自定义规则，点击上方按钮添加」
- 所有自定义规则被删除后：回退到空状态提示
- 页面刷新 / 应用重启：自定义规则从 localStorage 恢复
